# AGENTS.md — Vault Operating System

Every agent reads this file before making changes to the repository.

---

## Purpose

This repository is a **Dungeon Master Knowledge Factory**.

Goal: transform raw inspiration into reusable campaign assets via AI processing + human review.

Agent priorities (in order):

1. Reusability
2. Consistency
3. Traceability
4. Human review
5. Knowledge graph connectivity

Never create isolated content. Every entity must connect to at least one other entity.

---

## Pipeline

```
00-Inbox
    ↓
01-Processing   ← agents write here
    ↓
(human review)
    ↓
02-Library      ← humans promote here
    ↓
03-Campaigns / 04-Relationships / 05-Assets
```

Agents are only responsible for their assigned stage.  
No agent may bypass review requirements.  
No agent may promote content to `02-Library/` without `reviewed: true` in frontmatter.

---

## Directory Rules

### 00-Inbox/
- Never modify source files
- Never delete source files
- Preserve original filenames
- Subfolders: `images/` (by arc), `docs/`, `songs/`, `tokens/`

### 01-Processing/
- All AI output lands here
- Content is provisional until human approval
- File naming: slug format (see Naming Rules)

### 02-Library/
- Only approved content (`status: approved`, `quality >= 7`, `reviewed: true`)
- Every file must have full metadata + at least one relationship
- Canon: once approved, do not overwrite without explicit human action

### 03-Campaigns/
- Campaign-specific material (arcs, session notes, encounters)
- Reference Library entities via `[[wikilink]]` — do not duplicate content
- Subfolders mirror arc names: `A1-Annun/`, `A5-Cirit/`, etc.

### 04-Relationships/
- Auto-generated indexes: timelines, faction networks, location graphs
- Do not edit manually — regenerated by relationship agents

### 05-Assets/
- Approved media only: portraits, tokens, battlemaps, handouts
- Every asset must link to at least one Library entity
- Subfolders: `portraits/`, `tokens/`, `maps/`, `handouts/`

### 99-Archive/
- Retired content only
- Never permanently delete approved content — archive instead

## Metadata Standard

All `02-Library/` entities must use this frontmatter:

```yaml
---
id: {type}-{slug}
type: {entity-type}
status: draft | review | approved | archived
quality: 1-10
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags:
  - tag1
source:
  - filename.ext
reviewed: false
relationships:
  - "[[entity-slug]]"
---
```

Only agents with `reviewed: true` output in this repo: **none**. Humans set `reviewed: true`.

quest-missing-villagers.md
location-black-hollow-cemetery.md

## Linking Rules

Every entity needs at least one outbound wikilink.

| Entity | Must link to |
|--------|-------------|
| NPC | location, faction, or quest |
| Quest | NPC + location |
| Location | NPC or faction |
| Faction | NPC + location |
| Item | quest or owner NPC |
| Encounter | location + creature |

No orphan entities in `02-Library/`.

---

## Image Processing Rules

Input: `00-Inbox/images/`  
Output: `01-Processing/`

Required extraction per image:
- Subject, race, gender, age range, mood, environment
- Tags (for Obsidian search)
- Description (2–3 sentences)
- Suggested entity type
- 2–3 relationship hooks (NPCs, factions, locations this could connect to)

Do not generate lore that contradicts existing approved entities in `02-Library/`.

## Agent Definitions

### Ingestion Agent (`06-classify-images.ps1`)
- Detects new files in `00-Inbox/images/`
- Generates slug name, metadata, companion `.md` in same folder
- Updates `01-Processing/Images Index.md`
- Cannot modify `02-Library/`

### NPC Agent (`09-generate-npcs.py`)
- Reads image + scenario from `00-Inbox/images/`
- Generates NPC markdown draft in `01-Processing/`
- Tracks processed pairs in `.system/processed-npcs.json`
- Cannot approve content

### Token Agent (`10-generate-tokens.py`)
- Generates circular portrait tokens from character images
- Reads from `00-Inbox/images/`, writes `*-token.png` alongside source
- Tracks in `.system/generated-tokens.json`
- Cannot modify `02-Library/`

### Compile Agent (`03-compile-wiki.ps1`)
- Reads `00-Inbox/` markdown notes
- Generates synthesized pages in `01-Processing/`
- Tracks in `.system/processed.txt`
- Cannot approve content

### Enrich Agent (`04-enrich-tags.ps1`)
- Enriches `00-Inbox/` notes with additional tags via LLM
- Modifies frontmatter in-place
- Only touches notes with ≤5 tags

### Wiki Agent (future)
- Generates cross-links between `02-Library/` entities
- Updates `04-Relationships/` indexes
- Cannot modify metadata standards

## Quality Scoring

| Score | Status |
|-------|--------|
| 1–3 | Reject — do not promote |
| 4–6 | Review needed |
| 7–8 | Good — Library candidate |
| 9–10 | Excellent |

Agents suggest quality scores. Humans assign final scores.

## Canon Rules

- Approved content (`status: approved`) is canon
- Canon may not be overwritten by agents
- Canon may not be modified without `reviewed: true` re-set by human
- Historical references to canon entities must be preserved even if entity is archived
- Breaking canon requires explicit human git commit with reason in message
